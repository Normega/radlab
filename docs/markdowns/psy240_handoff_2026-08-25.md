## 0. Two things that will bite you immediately

**There are two Supabase MCP servers.** `supabase-academic` is the Field Guide
(`qldgwpneygvgcvexlduz`). Plain `supabase` is the main research platform. Wiki, roster,
gaps and claims live **only** in the academic project. Target destructive operations by
id, never by email.

**RLS testing via MCP is a trap.** The MCP connection is superuser and **bypasses RLS**.
`select set_config('request.jwt.claims', …)` alone proves *nothing* — a test that way
reported a student seeing all 270 pages and the whole roster, which was false. You must
also `set local role authenticated`:

```sql
begin;
select set_config('request.jwt.claims','{"sub":"<auth_user_id>","role":"authenticated"}',true);
set local role authenticated;
-- your check here
rollback;
```

`SECURITY DEFINER` functions with an internal `is_course_staff()` check test correctly
either way; **plain table reads do not**. Any earlier claim of "verified: non-staff sees
0 rows" on a plain table read should be redone.

## 5. Hard-won lessons — do not relearn these

- **The `identity` schema is not exposed to PostgREST.** `supabase-js`'s
  `.schema('identity')` fails with *Invalid schema*. Reach roster/people through
  `SECURITY DEFINER` RPCs granted to `service_role` only. Do **not** expose the schema —
  that is where the PII lives.
- **`gap_claims_guard` blocks every service-role path that doesn't introduce itself.**
  Set `radlab.claim_flow` (transaction-local) the way `claim_gap()` does. Three separate
  bugs came from this; expect a fourth when the quiz runner writes to claims.
- **supabase-js `.rpc()` reports failure in `error` — it does not throw.** An unchecked
  call returned `sent: true` while the write silently failed. Check every rpc error.
- **A guard rejection surfaced as a silent no-op is worse than a loud failure.**
- **The record is the source of truth, not the agent's report.** One audit subagent
  reported a full table and wrote 4 of 12 rows. Verify by querying for missing rows.
- **`edit_page`'s numeric tripwire fires on any figure change** and demands a
  verified-against-source statement. For internal-consistency fixes, say exactly that —
  *checked against the page's own figures, not the external source*.
- **Never `git add -A`.** Concurrent sessions share this checkout. Stage explicit paths.
  This session pushed to `main` via a temporary worktree
  (`git worktree add --detach <tmp> origin/main && merge && push HEAD:main`) to avoid
  disturbing another session's `dev` HEAD — a good pattern to reuse.
